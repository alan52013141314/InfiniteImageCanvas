# PR-008: Preload loading-placeholder regression
Date: 2026-10-11
User report: loading placeholders still appear with more than 2000 MB preload budget.
Scope: reproduce cache/decode behavior, fix proven causes, retain resource controls and provide verified explanation. No user files modified.

Acceptance: ready images within the preload budget must survive viewport transitions; foreground/background resolution tiers must agree; zooming out must reuse a sufficient cached tier. Nearest-first budgeting and zero-budget eviction remain effective in normal and both comic orientations.

Diagnosis: a real UI-frame test with a 400 × 300 PNG and 2048 MB setting fails on v0.4.1. Foreground requests a 512-pixel tier; offscreen preloading requests 400 and explicitly drops the ready texture to downsize. Returning to the image shows Loading while an unnecessary decode runs. This demonstrates cache disposal, not evidence of a slow GPU.

Fix: share resolution quantization, retain sufficient larger previews and count that larger tier in budget admission. Upgrade without blanking a ready preview. No new settings, dependencies or services.

Limits: background work remains asynchronous and active-tab-only. First loads, unfinished decoding and budget eviction can still show Loading. The configured MB value is a ceiling, additionally capped by available system memory; it does not make decoding faster or guarantee all images remain resident.
