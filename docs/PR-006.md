# PR-006: v0.4.0 preloading, gathering and comic reading

Date: 2026-10-11
Status: implemented and verified.

Confirmed requirements:
- Preserve viewport-only loading as default. Optional nearest-first preloading with application-wide persistent extra-memory budget; no worker-count setting.
- Keep top Settings and add Settings to blank-canvas right-click.
- Blank-canvas Gather here / Gather at image center: current-order touching grid, unchanged dimensions/proportions, bounds-centered anchor and Undo.
- Per-tab vertical/horizontal comic reading, current image order, original dimensions/proportions, restore original layout on exit.
- Ctrl+wheel zoom; wheel scroll along reading axis; corresponding arrows jump previous/next image.

Implementation details and boundaries:
- Extra preview budget defaults to 256 MB, configurable 0–65536 MB, capped by current available-memory budget. It is not a process-memory cap: decoding/GIF/work buffers require temporary memory.
- Active-tab preload uses a separate bounded background decoder; visible work keeps its existing decoder. Inactive previews are released. Duplicate sources are not charged repeatedly.
- Reading uses separate geometry/view; original canvas data and saved layout are untouched by reading navigation. Session metadata remembers direction, position and zoom. Source deletion cannot restore removed items on mode exit.
- Mixed-size gathering uses existing row-grid semantics; rows touch at their tallest boundary, without stretching images.
- No servers or unrelated features; no personal saves or images in release assets.
